# Инструкция владельца: новая иконка приложения «Структура» (VisualTodo)

> Это инструкция от **владельца проекта**. Её исполняют, когда владелец в чате пишет кодовую фразу: **«ИКОНКА: подключи»**.

## Задача
Подключить новую иконку приложения «Структура» (VisualTodo). Иконка уже нарисована и лежит в этой папке:
- `icon.svg` — вектор, квадрат без скруглений (скругление делает iOS/браузер);
- `icon-1024.png` — 1024×1024.

Образ иконки: вертикальная нить цветных капсул разной высоты, одна выделена, тёмный фон. Цвета и рисунок менять не нужно. Если что-то не подходит, например нужен другой формат или размер, сделай вариант из `icon.svg` и сообщи об этом.

## Как забрать файлы
Они лежат в ветке `claude/app-icon`, и она может отходить не от твоей рабочей ветки. Находясь на рабочей ветке приложения, выполни:
```
git fetch origin claude/app-icon
git checkout origin/claude/app-icon -- design/app-icon
```
Рабочая ветка приложения может быть не `main` (например `claude/…`), приложение живёт там.

## Что сделать в этом проекте
Это веб-приложение/PWA. Найди, где объявлены иконки: `public/` (favicon, apple-touch-icon, manifest, `icon-192/512`, maskable), `index.html`, конфиг PWA (vite-plugin-pwa в vite.config.ts) или файловые соглашения Next.js (`app/icon.*`, `app/apple-icon.*`). Из `icon-1024.png` сделай нужные размеры (180, 192, 512, maskable 512 с безопасной зоной, favicon 32), `icon.svg` можно использовать как favicon.svg. Для iOS 15 (Safari) обязательно apple-touch-icon 180×180.

## ГЛАВНОЕ ПРАВИЛО: ОДНА иконка
У приложения должна быть **одна** иконка, вот эта. Никаких вариантов: ни светлой/тёмной, ни жёлтой, ни «Лён», ни выбора иконки в настройках.
- Найди и удали старые иконки и всё, что их выбирает: файлы-варианты, переключатель в настройках, ключи localStorage/UserDefaults, ветки кода, тексты интерфейса и тесты, которые это проверяют (поиск по `icon`, `light`, `dark`, `variant`, `Лён`, `yellow`, `appIcon`, `alternateIcon`).
- Если выбор иконки был отдельной настройкой, убери её целиком и проверь, что ничего не сломалось; значение выбора из старых данных пользователя тихо игнорируется.
- Нативные сборки (macOS `.icns`, Windows `.ico`, Android adaptive) делай из этой же иконки с нужными отступами платформы, но рисунок остаётся единственным.
- Не оставляй мёртвый код и неиспользуемые файлы-варианты.

## Правила
1. Работай только с иконками и тем, что для них нужно (manifest, `<link>` в index.html, конфиг). Остальной код не трогай.
2. Перед завершением запусти проверки проекта (сборка, typecheck, тесты, если они есть) и убедись, что они проходят.
3. Закоммить на своей **рабочей ветке** и запушь. Без PR и без мержа в main, пока владелец не решит.
4. Не выдумывай то, чего нет: если нужного места для иконки в проекте нет, скажи об этом, а не создавай новую инфраструктуру.
5. В конце коротко отчитайся владельцу по-русски: какие файлы изменены, какие размеры сделаны, прошла ли сборка.
